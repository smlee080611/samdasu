암화병동 Godot 구조 설명서

1인칭 프로토타입을 씬과 노드 단위로 나눈 버전입니다. 각 씬을 어떤 노드로 만들고 어떤 스크립트를 붙이는지, 순서대로 따라 만들 수 있게 정리했습니다. 완성본 프로젝트도 함께 드립니다.

왜 나눴나

처음 프로토타입은 main.gd 하나가 벽, 사람, 문, UI를 전부 코드로 만들었습니다. 빨리 규칙을 확인하기엔 좋았지만 팀 작업에는 맞지 않습니다.

에디터에서 보인다

석상, 문, 차광막이 씬 트리에 노드로 있어서 끌어다 놓고, 인스펙터에서 값을 바꿀 수 있습니다.

맡은 파일만 고친다

광인 행동은 person.gd, 문은 door.gd. 서로 다른 파일이라 Git 충돌이 줄어듭니다.

그래픽 교체가 쉽다

모델을 바꾸려면 person.tscn의 메시만 교체하면 됩니다. 코드는 안 건드립니다.

빛 종류를 늘리기 쉽다

빛은 전부 같은 약속(light_value 함수 + 그룹)을 따르므로, 새 빛을 추가해도 기존 코드를 고치지 않습니다.

렌더러와 그래픽

렌더러는 Compatibility(OpenGL)입니다. 학교 PC나 노트북에서도 잘 돌고, 웹으로 내보낼 수 있습니다. 벽·바닥·천장·문·차광막은 textures/ 폴더의 픽셀 텍스처(벽 한 면 64 × 96px = 2m × 3m)를 씁니다. 머티리얼의 Texture Filter를 Nearest로 둬서 픽셀이 또렷하게 보입니다. 그래픽 담당은 이 PNG만 다시 그려 덮어쓰면 됩니다.

소리

sounds/의 WAV는 코드로 합성한 임시 효과음입니다. 같은 이름의 파일로 덮어쓰면 그대로 바뀝니다. 위치가 있는 소리(석상 깨짐, 광인 발소리, 문)는 Sfx.play_at(), 내 몸의 소리(발소리, 붙잡힘)는 Sfx.play()로 냅니다. 광인 숨소리는 person.tscn의 Breath 노드, 심장 박동은 player.tscn의 Heartbeat 노드, 배경 웅웅거림은 main.tscn의 Ambience 노드입니다. 심장 박동은 어둠 속 광인과의 거리, 굳음 수치에 따라 커지고 빨라집니다.

스크립트끼리 대화하는 방법

  • 그룹으로 서로를 찾습니다. "player", "level", "person", "light_source"(빛), "blocker"(길을 막는 것: 석상, 닫힌 문, 침대·카트·칸막이), "note"(쪽지).
  • Autoload 세 개(GameState, LightSystem, Sfx)는 어디서나 이름으로 부릅니다. GameState.say("..."), LightSystem.light_at(위치).
  • 함수 이름 약속(덕 타이핑): 상호작용 대상은 interact(), 길게 누르는 대상은 hold(), 화면 안내는 get_hint()를 가지면 플레이어가 알아서 씁니다.

1. Autoload 두 개

  1. scripts/autoload/game_state.gd, light_system.gd를 만듭니다. 둘 다 extends Node.
  2. 프로젝트 설정 → Autoload 탭에서 각각 이름 GameState, LightSystem으로 추가합니다.
스크립트하는 일주요 함수
GameState구출 수, 차광막 수, 게임오버·클리어 여부. 메시지·쪽지·상태 표시를 신호로 HUD에 보냄. ui_blocking이 켜지면(시작 연출, 쪽지 읽는 중) 플레이어·광인·배터리가 멈춤say(), open_note(), is_frozen(), add_rescued(), curtain_opened(), can_leave()
LightSystem"light_source" 그룹의 모든 빛에게 "이 위치에 얼마나 밝냐"를 물어 가장 큰 값을 돌려줌light_at(pos, exclude, safety_only), is_lit(), ray_clear()

핵심 설계. LightSystem은 빛의 종류를 모릅니다. 각 빛이 light_value(target, exclude)를 스스로 계산합니다. 그래서 석상은 "누가 비췄는지" 몰라도 되고, 빛을 새로 만들어도 석상 코드는 그대로입니다.

2. Level (level_1f.tscn)

Level1F (Node3D) scripts/objects/level.gd
├ People   (Node3D)  정리용 빈 노드
├ Doors    (Node3D)
├ Curtains (Node3D)
├ Lights   (Node3D)
├ Pickups  (Node3D)
└ Stairs   (stairs.tscn 인스턴스)
  1. Node3D를 루트로 만들고 level.gd를 붙입니다.
  2. 인스펙터의 Wall Map에 벽 지도를 글자로 입력합니다. #은 벽, .은 바닥. 한 칸 = 2m.
  3. Entrance Tile(입구 칸), Wall / Floor / Ceiling Material을 지정합니다. 텍스처는 벽 한 면, 바닥 한 칸마다 한 장씩 정확히 붙습니다.
  4. 정리용 빈 Node3D들 아래에 석상·문·차광막 씬을 끌어다 놓습니다. 칸 중심 좌표는 (x × 2 + 1, 0, y × 2 + 1).

level.gd가 하는 일: 지도대로 벽 충돌 상자를 만들고, 그래픽은 바닥 쪽으로 드러난 벽 면만 사각형으로 이어 붙여 하나의 메시로 만듭니다(SurfaceTool). 바닥·천장도 칸마다 사각형입니다. 그리고 AStarGrid2D로 칸 단위 길찾기를 제공합니다. 석상이 생기거나 문이 바뀌면 refresh_nav()로 갱신합니다.

나중에 바꿀 수 있는 부분. 벽을 글자 지도로 만든 건 속도 때문입니다. 레벨 디자이너가 익숙해지면 GridMap + MeshLibrary로 바꿔도 is_walkable()만 고치면 나머지는 그대로 동작합니다.

모델을 바꾸려면 Model 노드를 다른 .glb로 교체합니다. 팔다리가 움직이려면 같은 부위 이름(Head, Torso, ArmXp/ArmXn, LegXp/LegXn)과 관절 원점을 지켜야 합니다. person.gd는 인스펙터의 Skin 재질을 사람마다 하나 복제해서 모든 부위에 씌우고, 상태 색(석상 회색, 광인 붉은빛, 회복 원래 색)을 바꿉니다. 석상은 처음에 사람마다 다른 자세(고개 꺾임, 팔을 뻗음)로 굳어 있습니다.

석상, 광인, 회복한 사람은 같은 씬 하나입니다. state 값만 바뀝니다.

STATUE ──빛을 받음──▶ MAD ──빛을 계속 받음──▶ CURED ──입구 도착──▶ 구출
   ▲                        │
   └──어둠 속 6.5초──────────┘
상태행동그룹
STATUE빛을 받으면 body_t가 차오르며 몸이 주황색으로 달아오름. 1이 되면 광인blocker (길을 막음)
MAD빛 속: 정신(sanity)이 돌아오는 동안 플레이어 시야 밖의 어두운 곳(벽 뒤, 모퉁이 너머)을 찾아 도망침(_plan_escape). 숨은 뒤엔 1.5~3.5초 엿보다가 다시 다가옴. 도망칠 곳이 없으면(구석에 몰림) 0.9초 버티다가 비명과 함께 돌발 돌진, 빛 속이어도 붙잡을 수 있음(3.5초에 한 번). 붙잡은 뒤엔 1.6초 물러섬. 빛을 맞는 순간 움찔. 어둠 속: 멀리서는 슬금슬금, 5칸 안이면 돌진·멈춤 반복. 6.5초 지나면 플레이어를 바라보며 다시 석상—
CURED현관 밖 마당(exit_tile)까지 걸어가 구출 처리. 정신이 막 돌아와 길을 잘 몰라서, 갈림길에서 가끔 엉뚱한 쪽으로 가고(confusion 28%) 멈춰서 두리번거림. 플레이어가 5칸 안에 있으면 플레이어를 따라옴(호위). 길이 막히면 멈춤. 빛을 가리지 않고 플레이어와 겹쳐 지나갈 수 있음. 어둠 속에서 광인에게 붙잡힐 수 있음: 주저앉아 "살려주세요…!"(멀리서도 들림), 5초(hold_petrify) 동안 굳어 가다가 석상이 됨. 그 안에 빛이 닿으면 광인은 놓고 도망치고, 사람은 다시 일어나 걸어감. 엘리베이터 홀에서 기다리는 사람은 안전—

부드러운 이동: 칸 중앙에 멈추지 않고 0.45m 전에 다음 칸을 정해서 모퉁이를 둥글게 돕니다. 사람마다 걷는 줄(lane)이 조금씩 다르고, 속도는 서서히 바뀌고, 몸은 천천히 돕니다. 개인차: 사람마다 속도 ±15%, 돌진 거리 ±1칸, 다시 굳는 시간이 다릅니다.

시간: 센 빛으로 정신이 돌아오는 데 약 10초(sanity_speed 0.1). 어둠 속에서 다시 완전히 굳는 데는 풀린 정도에 비례해 5초(막 깨어남)~25초(거의 다 풀림)가 걸립니다(petrify_min, petrify_max). 도망 속도는 2.4~4.4m/s로 빠릅니다.

풀릴수록 빨라진다. 광인의 속도는 sanity(0~1)에 따라 변합니다. 막 깨어난 광인은 뻣뻣하고 느리고(쫓는 속도 1.6m/s), 빛을 받아 풀릴수록 매끄럽고 빨라집니다(4.6m/s, 플레이어 3.2m/s보다 빠름). 그래서 반쯤 비추다 놓치면 가장 위험한 광인이 됩니다. 끝까지 비추면 정신이 돌아옵니다.

움직임: 뼈대 없이 _animate()와 _limb_pose()가 부위를 돌립니다. 다리를 엇갈려 휘두르고, 광인은 팔을 앞으로 뻗고(돌진할수록 높이), 고개가 확 꺾이는 경련이 있습니다. 뻣뻣할수록 보폭이 작고 스톱모션처럼 초당 6장만 보이며(풀리면 30장), 다시 굳을 때는 그때 자세 그대로 굳습니다. 나중에 Mixamo 애니메이션을 넣으면 이 위에 경련만 얹으면 됩니다.

어둠 속에서 다시 굳어 감: 광인이 어둠에 있으면(dark_t) 점점 느려지고, 움직임이 더 끊기고, 몸이 회색으로 변하다가 6.5초에 석상이 됩니다. 이때 플레이어를 바라보며 굳습니다.

인스펙터에서 바꿀 수 있는 값: person_name, wake_speed, sanity_speed, petrify_after, chase_range, rush_range, 뻣뻣할 때·풀렸을 때 속도(쫓기·도망 각각), walk_out_speed. 밸런스 조정은 코드 대신 여기서 합니다.

엘리베이터 표시등한 명 이상 구한 뒤 홀에 처음 돌아왔을 때멈춘 엘리베이터 표시등이 붉게 깜빡이고 전기 소리. 비상발전기 떡밥
사라진 사람홀에 두 명 이상 모인 뒤 25초 넘게 멀리 있을 때한 명이 108호로 걸어가 어둠 속에서 다시 굳음. 구출 수 −1

8. Main (main.tscn)

Main (Node3D) main.gd
├ WorldEnvironment    배경 검정, 주변광 0.04, 안개 0.035
├ Level1F   (level_1f.tscn 인스턴스)
├ Player    (player.tscn 인스턴스, 위치 5, 0, 19 = 엘리베이터 홀)
├ HUD       (hud.tscn 인스턴스)
└ Events    (Node, events.gd)  공포 사건

main.gd는 시작할 때 GameState.reset(), R을 누르면 씬 다시 불러오기만 합니다. 층이 늘어나면 여기서 Level 씬을 바꿔 끼우면 됩니다.

확장하는 법

예시 1. 촛불(새 빛) 추가

  1. OmniLight3D로 candle.tscn을 만들고 point_light_source.gd를 붙입니다.
  2. range 3, power 0.6 정도로 설정합니다. 끝. 석상이 알아서 반응합니다.

예시 2. 밀 수 있는 침대(빛 가림막) 추가

  1. StaticBody3D, layer는 wall(1)로 둡니다. 빛 판정 레이캐스트가 wall을 보므로 자동으로 그림자가 됩니다.
  2. 길도 막게 하려면 "blocker" 그룹에 넣고, 움직인 뒤 level.refresh_nav()를 부릅니다.
  3. E로 밀게 하려면 interact(by) 함수를 만듭니다. 플레이어 코드는 고칠 필요가 없습니다.

예시 3. 직업별 광인

person.tscn을 상속한 씬(nurse.tscn 등)을 만들고 인스펙터 값(속도, 회복 속도)과 메시만 바꿉니다. 행동이 많이 다르면 person.gd를 상속한 스크립트에서 _mad()만 덮어씁니다.

실행과 점검

  1. 압축을 풀고 Godot 4.3에서 project.godot을 엽니다.
  2. F5로 실행. 화면을 클릭하면 마우스가 잠기고, Esc로 풀립니다.
  3. 목표: 차광막 3개 걷기 + 3명 구출 + 양 끝 비상계단 중 하나. 시작은 가운데 엘리베이터 홀. 에디터 실행 중에는 F1로 진행 상황 확인(개발용).

자동 점검: 터미널에서 godot --headless --path . -- selftest. 석상 깨우기 → 광인 → 랜턴으로 회복 → 문 열고 닫기 → 차광막 걷기 → 상호작용 레이캐스트까지 차례로 실행하고 결과를 출력합니다. 이 설명서와 함께 드린 프로젝트는 이 점검을 모두 통과했습니다. 다만 화면 밝기와 색감은 사람 눈으로 확인이 필요합니다.
